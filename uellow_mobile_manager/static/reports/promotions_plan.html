نسخة المسودّة · مبني فوق mobile.app.promotion الحالي

الوضع الحالي (ما عندنا): موديل mobile.app.promotion = حملة بشارة (badge) + بانر + انضمام تجّار + أسطر منتجات يدوية بنسبة خصم تُطبَّق على السعر مباشرة.
الهدف: تحويله إلى محرّك خصومات قائم على قواعد (Rules Engine) باستهداف ذكي + شروط + مكافآت متعددة + تحكّم بالقناة + حارس ربح + هدايا/شحن/كوبونات.

١) الاستهداف — على مَن يُطبَّق العرض؟ (Scope)

بدل اختيار المنتجات يدوياً فقط، أضف "نطاقات" (scopes) تُجمَع بعلاقة AND/OR:
  • كاتيجوري (واحدة أو أكثر، مع/بدون الأقسام الفرعية).
  • براند (product.brand / قيمة سمة Brand).
  • نطاق سعري من/إلى (مثلاً 5–20 د.ك).
  • منتجات محدّدة (القائمة اليدوية الحالية تبقى).
  • تاجر/Vendor معيّن.
  • وسوم/Tags (جديد، الأكثر مبيعاً، بطيء الحركة/Dead stock، موسمي…).
  • حالة المخزون (متوفّر فقط / يشمل النافد).
  • استبعادات (Exclusions) — استثنِ كاتيجوري/براند/منتجات من النطاق.
  • الكل (Sitewide) كخيار سريع.
تقنياً: نبني domain ديناميكي من النطاقات، ونخزّن النتيجة كـ "preview count" قبل التفعيل.

٢) الشروط — متى يُفعَّل العرض؟ (Conditions / Rules)

شروط السلة

  • حد أدنى لإجمالي السلة (Min subtotal).
  • حد أدنى لعدد القطع/المنتجات.
  • حد أدنى من نفس الكاتيجوري/البراند.
  • "اشترِ X من الفئة لتحصل على…".

شروط العميل

  • أول طلب فقط (عميل جديد).
  • شريحة عملاء (VIP / مستوى ولاء / مدينة).
  • عميل لم يطلب منذ X يوم (re-engagement).
  • عيد ميلاد العميل (partner.uellow_birthdate).

شروط زمنية

  • تاريخ بداية/نهاية (موجود).
  • أيام/ساعات محدّدة (Happy Hour، عطلة نهاية الأسبوع).
  • عدّاد تنازلي (Flash).

شروط أخرى

  • الدولة/الموقع (per-website، عندنا 17 موقع).
  • طريقة الدفع (مثلاً خصم للدفع بـKNET/Taly).
  • كود ترويجي مُدخل (Promo code).
  • قناة الدخول (حملة /aff، إعلان…).

٤) التحكّم بالقناة — موبايل فقط أم موبايل + ويبسايت

حقل channel Selection: موبايل فقط ويبسايت فقط موبايل + ويبسايت POS أيضاً
نقاط التطبيق تحترم القناة:
  • الموبايل: عبر serialize_product_card + cart.py (سعر فعّال) + بطاقة المنتج.
  • الويبسايت: عبر pricelist/سعر القائمة + بادج المتجر.
  • "موبايل فقط" لا يلمس أسعار الويبسايت إطلاقاً (تطبيق وقت العرض لا بالكتابة على list_price).
ملاحظة مهمة: الموديل الحالي يكتب على list_price مباشرة (يؤثر على كل القنوات). للتحكّم بالقناة نحتاج تطبيق الخصم "وقت العرض/الحساب" بدل تعديل سعر المنتج — انظر قسم البنية.

٥) ⭐ حارس الربح — خصم حسب نسبة الربح (Margin Guardrail)

أهم فكرة طلبتها: لا يُسمح لأي خصم أن يأكل الربح تحت حدّ معيّن.
  • لكل منتج تكلفة standard_price ⇒ الربح = (السعر − التكلفة) / السعر.
  • إعداد الحد الأدنى للربح % (عام + لكل كاتيجوري + override لكل منتج).
  • وضعان:
    • سقف تلقائي: تحدّد خصم 30%، والنظام يقصّه لكل منتج بحيث لا ينزل الربح تحت الحد (مثلاً منتج هامشه ضعيف يأخذ 12% فقط).
    • اشتقاق من الهامش: تقول "اترك لي ربح 15%" والنظام يحسب أقصى خصم ممكن لكل منتج تلقائياً.
  • منتجات لا تحقّق الحد الأدنى للربح ⇒ تُستبعَد من العرض تلقائياً (مع تقرير بها).
  • لوحة معاينة: "هذا العرض سيطبّق خصماً متوسطه X% على N منتج، ويحافظ على ربح ≥ Y%".
قراءة standard_price تحتاج صلاحية كاملة (SUPERUSER) — معروف من كونسول الأدمن.

٦) أفكار تحكّم إضافية (كثيرة كما طلبت)

التكديس والأولوية

  • قابل للتكديس مع عروض أخرى أم حصري (Exclusive).
  • أولوية/تسلسل عند تطابق أكثر من عرض.
  • "الأفضل للعميل دائماً" (best-deal wins).

السقوف والميزانية

  • سقف استخدام كلي (أول 100 طلب).
  • سقف لكل عميل (مرة واحدة/يوم/شهر).
  • سقف ميزانية الخصم (يتوقف عند صرف X د.ك).

العرض والبصريات

  • بادج + بانر (موجود) + لون/إيموجي.
  • عدّاد تنازلي + "بقي N قطعة".
  • بلوك مخصّص بالـPage Builder (source=promotion موجود).
  • إشعار Push تلقائي عند إطلاق العرض (push_event موجود).

الذكاء والتجارب

  • A/B: نسختان من العرض وقياس التحويل (uellow.ab.test موجود).
  • استهداف بالذكاء (Brain): للمنتجات بطيئة الحركة.
  • جدولة متكرّرة (كل جمعة).
  • تقرير أداء: مبيعات/ربح/استخدام لكل عرض.

٧) البنية المقترحة (Models)

  • mobile.app.promotion (نوسّعه): + channel, stackable, priority, exclusive, usage_limit, per_customer_limit, budget_cap, min_margin_pct, margin_mode, حقول الجدولة بالساعات/الأيام.
  • mobile.promo.scope (جديد): سطر نطاق (نوع: category/brand/price_range/product/vendor/tag + قيمة + تضمين/استبعاد).
  • mobile.promo.condition (جديد): سطر شرط (min_subtotal/min_qty/first_order/segment/payment/day…).
  • mobile.promo.reward (جديد): سطر مكافأة (percent/fixed/price/bogo/free_gift/free_ship/coupon_apply/coupon_generate/loyalty_x).
  • إعادة استخدام: uellow.freeship.rule للشحن، loyalty.program للكوبونات، uellow_bundles لباقات الهدايا.
نقاط التكامل (Integration points): cart.py → effective_price (الخصم وقت الحساب)، serialize_product_card (بادج/سعر)، block_resolver (بلوكات)، إضافة هدية إجبارية في منطق السلة، تطبيق الكوبون التلقائي عند تأكيد السلة.

٨) خطوات التنفيذ (Phased Roadmap)

المرحلة 0 — قرار معماري (نصف يوم): تحويل تطبيق الخصم من "الكتابة على list_price" إلى "خصم وقت العرض/الحساب" — شرط أساسي لتحكّم القناة وحارس الربح وعدم تلويث الويبسايت.
المرحلة 1 — الاستهداف بالقواعد: نماذج mobile.promo.scope + بناء domain ديناميكي + معاينة عدد المنتجات. (كاتيجوري/براند/نطاق سعري/استبعادات)
المرحلة 2 — حارس الربح: قراءة standard_price، إعدادات الحد الأدنى للربح (عام/كاتيجوري/منتج)، وضعا السقف والاشتقاق، استبعاد غير المربح + تقرير معاينة.
المرحلة 3 — التحكّم بالقناة: حقل channel + احترامه في الموبايل/الويبسايت/POS، وفصل أسعار الموبايل عن الويبسايت.
المرحلة 4 — الشروط: mobile.promo.condition (سلة/عميل/زمن/دفع) + محرّك تقييم الشروط في السلة.
المرحلة 5 — المكافآت الغنية: هدية إجبارية بالكارت + تفعيل الشحن المجاني + كوبون إجباري/توليد كوبون + BOGO + نقاط مضاعفة.
المرحلة 6 — السقوف والتكديس: usage/per-customer/budget caps + الأولوية/الحصرية + best-deal.
المرحلة 7 — العرض والقياس: بادج/بانر/عدّاد + إشعار إطلاق تلقائي + تقرير أداء (مبيعات/ربح/استخدام) + A/B.
المرحلة 8 — الويبسايت: مزامنة العرض على المتجر (قاعدة "كل ميزة تطبيق تظهر على الويبسايت").

٩) قرارات أحتاجها منك قبل البدء

  1. هل نوسّع mobile.app.promotion الحالي أم ننشئ موديلاً جديداً mobile.promo.rule ونُبقي القديم للبادجات؟ (أرشّح التوسيع التدريجي).
  2. تطبيق الخصم: "وقت العرض/الحساب" (مرن، يحترم القناة) — موافق؟ (أرشّحه بقوة).
  3. أولوية المراحل: أبدأ بأي ٣ مراحل؟ (أرشّح 1 الاستهداف + 2 حارس الربح + 5 الهدايا/الشحن/الكوبون).
  4. الهدية الإجبارية: تُضاف تلقائياً وتُمنع إزالتها — هل تظهر بسعر 0 أم كخصم 100%؟
